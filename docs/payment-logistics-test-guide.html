第 0 步修正本機的綠界商店代號

只影響本機，正式站不受影響。不改的話，第 1 層的 A2 與第 2 層的金流測試都會在綠界頁面失敗。

  1. 打開 repo 根目錄的 .env，把 ECPAY_MERCHANT_ID 改成 .env.example 裡的官方測試代號 3002607（HashKey／HashIV 已經是對應的那組，不用動）。
  2. 重啟網站與背景程式： 
    docker restart sagon-web-1 sagon-worker-1

為什麼會這樣　商店代號、HashKey、HashIV 是一組的，要嘛全用測試的，要嘛全用正式的。正式的那一組只放在 docs/sagon-deploy/.env.production，不要搬進本機的 .env。

第 2 層準備：開一條公開網址

讓綠界的付款通知、取號通知、物流貨態打得進你的電腦。

  1. 啟動 tunnel： 
    docker compose --profile tunnel up -d cloudflared
  2. 從 log 找出 https://xxxx.trycloudflare.com 這行： 
    docker compose logs cloudflared
  3. 把這個網址填進 repo 根目錄 .env 的 APP_URL 與 NEXT_PUBLIC_APP_URL（先記下原本的值，測完要改回來），然後重啟網站與背景程式： 
    docker restart sagon-web-1 sagon-worker-1
  4. 瀏覽器開 https://xxxx.trycloudflare.com/api/health，回 200 就成功。之後的測試都從這個網址操作，不要再用 localhost。

注意　trycloudflare 的網址每次重啟都會換，換了就要重填 .env 並重啟。測到一半 tunnel 斷掉，那段時間的通知都會遺失（可用 A2 的方法補）。

測試時開一個終端機看背景程式的動作，建單失敗、寄信失敗都會在這裡出現：

docker logs -f sagon-worker-1

更完整的上線測試（含正式金鑰檢查與失敗回退）見 docs/go-live-test-plan.html。

測完收尾（本機）

  1. 把 .env 的 APP_URL、NEXT_PUBLIC_APP_URL 改回原本的值，執行 docker restart sagon-web-1 sagon-worker-1。
  2. 關掉 tunnel：docker compose stop cloudflared。
  3. 測試訂單留在本機資料庫沒關係，正式站的資料庫是另一個。
  4. 本機 .env 的 ECPAY_MERCHANT_ID 保持 3002607，不要改回正式代號。
  5. 黑貓託運單 PDF 的備份留著，24 小時後就不能再向黑貓下載。

出錯時怎麼辦

  1. 先停，不要重試、不要重按按鈕。重按黑貓建單會多一張真的託運單。
  2. 截圖當下畫面，記下訂單編號與時間。
  3. 蒐集證據：docker logs sagon-worker-1 的錯誤訊息、後台「Webhook」那筆事件的原始內容、訂單頁的紅字。
  4. 把「做了什麼 → 預期 → 實際 → 證據」記下來，再決定要修還是繼續。外部服務暫時掛掉造成的失敗，可以用 scripts/enqueue-job.ts 補跑。

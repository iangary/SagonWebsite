這次加了什麼

新增與編輯組合的頁面最上方多了一個「用 JSON 設定」區塊：

  • 套用到表單：貼上 JSON，一次填好整份表單，確認後再按「建立組合」。
  • 套用並建立／套用並儲存：貼上就直接存檔。
  • 從目前表單產生 JSON：把現有組合匯出，複製去改成另一個組合，或留存備份。
  • 填入範例、欄位說明：不用記格式。

商品可以用 slug、ID 或完整商品名稱 指定，規格可以用 SKU、規格名稱或 ID 指定，"variant": null 代表任一規格（顧客自選）。 JSON 只負責把表單填好，存檔仍走原本的表單送出，由伺服器做最終驗證（組合價必須低於原價、上架時商品都要在架上），所以不會因為 JSON 繞過任何檢查。

測試中發現並已修正的問題

類型問題處理檔案
使用體驗套用 JSON 後面板收合、貼上的內容消失面板移到不會重新掛載的外層。套用後 JSON 仍在，可以對照表單、改一個字再套用一次。bundle-form.tsx
Bug「套用並儲存」會送出兩次（稽核紀錄多一筆 bundle.update）開發模式的 StrictMode 會把 effect 跑兩次。加上只送一次的保護，重測後只有一筆。bundle-form.tsx
既有 Bug組合表單 hydration mismatch（Next 左下角出現 1 Issue）原本列的 id 用模組層級的計數器產生，伺服器每次請求都會累加。改成初始列用索引、新增列才遞增，連續三次請求都輸出 row-1。bundle-form.tsx
版面購物車摘要裡組合名稱太長時，「-」和「NT$1,550」被拆成兩行金額欄不換行，讓左邊的組合名稱換行。cart-view.tsx
版面「整組加入」後購物車商品的順序會跳動同一個交易建立的幾筆 createdAt 完全相同；排序補上 id 當第二順位，順序固定。lib/cart/shared.ts

截圖中步驟 1 是修正「面板收合」前拍的，面板外觀相同；步驟 10 是修正「順序跳動」前拍的，所以枕頭套排到了最後。

自動化測試

  • JSON 單元測試 8 個（bundle-json.test.ts）：
    • slug／ID／名稱與 SKU／規格名稱都能對上。
    • 語法錯誤會指出大約第幾行。
    • 必填欄位與型別錯誤一次全部列出。
    • 找不到商品、規格不存在、名稱有歧義、數量超出範圍都會擋下。
    • 不認得的欄位只警告不擋。
    • 匯出後再匯入，值完全不變。
  • 整合測試：用真實資料庫跑「JSON → 解析 → saveBundle 存進資料庫 → 前台算出原價與現省」。組合相關的整合測試共 25 個。
  • 全套：tsc --noEmit 通過、eslint 沒有新的問題、vitest run 71 個檔案、1,068 個測試全數通過。

沒有涵蓋的部分

  • 沒有在瀏覽器實際送出訂單和付款（開發站的綠界 callback 打不到 localhost）。下單金額、逐件扣庫存、綠界金額比對，由先前的整合測試涵蓋。
  • JSON 面板只在桌機寬度測試，沒有特別檢查手機版後台。
  • 一次只能設定一個組合；JSON 最外層是陣列（批次建立多個組合）會被拒絕。

測試後的資料狀態

  • 開發庫裡留著測試組合「Maison de Paris 法式居家三件組」（上架中、NT$7,990），可以在後台看，不需要時按「刪除」即可。
  • 測試時放進管理員購物車的商品已清空（測試前就是空的）。
  • 這次的修改都還沒有 commit。

正式 SMTP 寄信服務評估（L-05）

2026-08-17 ｜ 對應 docs/test-checklist.html L-05、docs/manual-test-stage.md M-8 ｜ 分支 main

問題：台灣有沒有合適的寄信服務？改用 Google 的服務可不可以？本文把兩條路都查完，跟目前 docs/deploy.md §6 已寫的 Resend 放在一起比。

🇹🇼 台灣本土 — 不建議當主力

能算數的只有電子豹 Surenotify 一家。它沒有 SMTP relay，只有 HTTP API，等於要改掉 src/lib/email.ts 的 nodemailer；單價還貴 40–80 倍。

🔵 Google — 買來收信可以，寄程式信不行

Workspace 值得買一組 service@chenkuanyi.com.tw 當客服信箱。但 smtp.gmail.com / smtp-relay.gmail.com 沒有退信 webhook、額度按收件人算、超額鎖 24 小時，訂單信不能押在上面。

✅ 維持 Resend，SES 當備援

免費 3,000 封/月已覆蓋現在的量，有 SMTP relay、有東京節點。但免費方案有 100 封/日上限——建議一開站就升 Pro（US$20/月）或先把 SES 開好。

1. 我們到底要寄什麼（需求盤點）

先把需求釘死，不然比較表會失焦。從原始碼盤點：

量級估算。沒有實際營運數字，用訂單數推：

50 筆（開站初期）約 120 封含少量取消信

硬需求（用來刷掉選項）

  • 要有 SMTP relay。沒有的話得改寫 src/lib/email.ts，把 nodemailer 換成該家的 HTTP SDK，連帶影響本機 Mailpit 開發流程與 test/integration/email-notifications.test.ts。這是實打實的工。
  • 要能驗自訂網域的 DKIM。信要從 mail.chenkuanyi.com.tw 出去，不能是供應商的網域。
  • 要有退信／申訴（bounce / complaint）可見。否則 L-03 的 5 次重試會對著不存在的信箱狂打，反而傷網域信譽。
  • 要 API key 認證。SMTP_PASS 放的是 API key，可隨時撤換，不是某個人的信箱密碼。

不需要的：EDM 模板編輯器、A/B 測試、名單管理、自動化流程。這些是 EDM 平台的賣點，我們一項都用不到——這點很關鍵，因為台灣廠商賣的正好都是這些。

2. 台灣本土的選項

我把「台灣廠商」拆成三類來看：交易信平台、電信商信箱、自架。

2.1 電子豹 Surenotify（唯一真正對口的台灣廠商）

電子豹（Newsleopard）是台灣做電子報最久的一家，Surenotify 是它拆出來的交易信／簡訊 API 產品。這是台灣市場上唯一定位正確的選項。

面向結論
介接方式致命傷 只有 HTTP API（POST https://mail.surenotifyapi.com/v1/messages，x-api-key 標頭）。官方文件沒有任何 SMTP relay 主機／埠號
網域驗證有 SPF／DKIM 都能用 TXT 或 CNAME 驗自己的網域
價格訂閱制，月費 NT$600／2,200／8,000／15,200 四檔，對應每封 NT$0.24／0.20／0.16／0.13。月費可折抵用量，等於最低消費 NT$600／月
單次上限每次請求最多 100 個收件人（我們一次一封，無感）
好處中文客服、可簽台灣合約、開台灣統一發票、資料留在台灣、出事找得到人

為什麼「只有 API」在我們這裡是致命傷。src/lib/email.ts 現在是 nodemailer + SMTP，本機開發指向 Mailpit（127.0.0.1:1025）。換成 Surenotify 要動三處：getTransporter() 整段換掉、本機開發得另想辦法攔信、整合測試的假 SMTP 也要跟著改。這不是不能做，但為了一個「貴 40 倍又要改碼」的選項做，不划算。

價格對照直觀一點：3,000 封／月，Surenotify 約 NT$720，Amazon SES 約 NT$10，Resend 免費。差距不是幾成，是兩個數量級。台灣廠商的價格是照「EDM 每封計價」的商業模式定的，而 EDM 每封本來就比交易信貴——它賣的是名單管理與投遞率服務，不是純管道。

2.2 中華電信企業郵件 / HiNet 信箱

不適用 這一類（msa.hinet.net、企業郵件、U-Mail 等虛擬主機商附的信箱）本質是給人收發信的信箱服務，不是交易信平台：

  • 沒有退信 webhook、沒有投遞紀錄 API，信寄丟了你不會知道。
  • 額度是個人信箱等級的每日上限，且以「收件人」計。
  • HiNet 自 2025 Q4 起強制 SMTP 帳密認證——那是把「某個人的信箱密碼」寫進 .env.production，跟「API key 可隨時撤換」是兩回事。
  • 用 @hinet.net 的位址寄，MAIL_FROM 就不可能對齊 chenkuanyi.com.tw，DMARC 直接不通。

2.3 自架 Postfix（主機 103.1.221.67）

不要做 三個理由，任一個都足以否決：

  • 25 埠幾乎必定被機房封鎖（docs/deploy.md §6 已經寫了這件事）。
  • 單一 VPS 的 IP 沒有寄信信譽，Gmail／Yahoo 對新 IP 極不友善，一開始就是垃圾桶起跳，要「養 IP」數週。
  • 2024 年起 Gmail／Yahoo、2025 年起 Outlook 陸續強制 SPF＋DKIM＋DMARC 與退信率門檻。自架代表這些全部自己扛，出事沒有人可以問。

2.4 「台灣機房 + 台灣資料落地」目前無解

AWS 台北區 ap-east-2 已經開了，但沒有 SES（2026-08 服務清單裡 SES 只到東京、首爾、大阪、新加坡、雪梨等）。Resend 有東京節點可選，但資料仍存在美國（官方明說 region 只影響寄送出口，不改資料落地政策）。

所以如果「收件人姓名／email 不得離境」是硬條件，唯一解就是電子豹。如果不是硬條件（一般電商並非如此），這個維度不該主導決策。

台灣這條路的一句話結論：有一家做得對（電子豹 Surenotify），但它為了 EDM 客群設計，價格與介接方式都不適合我們這種「一天幾十封、已經寫好 nodemailer」的小電商。值得選它的唯一理由是「必須有台灣合約／發票／在地客服／資料不出境」——如果這些對你重要，那它是好選擇，代價是改碼加每月 NT$600 起。

3. Google 的三條路

「用 Google 的服務」其實混了兩件不同的事，要拆開講。

3.1 拿 Google 當寄信管道

四個真正勸退的理由（不是額度問題，是機制問題）：

  1. 沒有退信／申訴 webhook。Resend／SES 會回報 hard bounce 與 spam complaint，我們可以停止重試、標記壞信箱。Google 這條路只會退一封 NDR 到某個信箱——L-03 的 5 次重試會盲目重打。
  2. 額度按「收件人」計、以滾動 24 小時計算，超額鎖最多 24 小時。訂單信是不能停的東西。真的撞到上限，那一整天的付款成功信全部寄不出去，而且是靜默失敗。
  3. Google 不把它當交易信平台。SMTP relay 的官方定位是「印表機、掃描器、內部應用程式」。拿它當電商的對外訂單通知管道是超出設計意圖的用法，出事沒有支援可談。
  4. IP 白名單綁死主機。relay 走 IP 認證，103.1.221.67 一旦換機或加節點就要回後台改。

3.2 拿 Google Workspace 當客服信箱 —— 這個值得買

這是本次評估唯一真的建議你花錢的地方。.env.example 目前 SHOP_SERVICE_EMAIL=ian890711@gmail.com，而這個位址會出現在每一封通知信的頁尾、頁尾／關於／聯絡／常見問題與各政策頁（見 src/lib/email.ts:47 的註解）。一間有統編的店，客服信箱掛 @gmail.com，觀感差；而且客人的回信會落進你的私人信箱，沒有轉手、沒有備援。

Business Starter 自 2026-01-16 起 US$7／人／月（約 NT$224）。買一組 service@chenkuanyi.com.tw 就夠。2026-08-30 至 11-30 有五折活動（US$3.5），時間剛好。

買了 Workspace 之後，寄信仍然走 Resend／SES。兩者不衝突：Workspace 管 chenkuanyi.com.tw 的 MX（收信），Resend 管 mail.chenkuanyi.com.tw 子網域的寄出（發信）。DNS 上互不干擾。

6. 建議

主案：維持 Resend，開站時直接上 Pro

docs/deploy.md §6 已經寫的方案是對的，不用換。理由：有 SMTP relay（不動一行程式碼）、有東京節點、DKIM 設定最省事、退信 webhook 齊全。

唯一要修正的是免費方案的「每日 100 封」。月額度 3,000 封看起來很夠，但日上限 100 封換算下來只有每天約 40 筆訂單。平常沒事，檔期或上新品衝一波就會撞到，而且撞到的後果是「付款成功信整批寄不出去」——客人付了錢沒收到信，客服電話就來了。

US$20／月（約 NT$640）買掉這個風險，是這整份評估裡最划算的一筆。或者維持免費方案，但先把 Amazon SES 的 sandbox 解掉放著當備援（解 sandbox 要等審核，不能等出事才辦）。

備案 A：Amazon SES（東京）

如果願意多花半天處理 sandbox 申請與 IAM 設定，SES 是長期成本最低、規模上限最高的。適合「這個站會做很久、量會長」的判斷。缺點是後台難用、退信率超標會被停權（要自己接 SNS 處理 bounce）。

備案 B：ZeptoMail

US$2.50／萬封、有 SMTP、純交易信定位。介於 Resend 的方便與 SES 的便宜之間。唯一要注意的是點數六個月到期，量小的話會有一點浪費。

不建議

  • 電子豹 Surenotify——除非「台灣發票／合約／資料不出境」是硬性要求。它要改掉 nodemailer，且是唯一會產生固定月費的選項。
  • Google 當寄信管道——沒有退信 webhook、額度按收件人算、超額靜默鎖 24 小時。
  • 自架 Postfix——25 埠被封、IP 沒信譽、三大認證全部自己扛。

另外建議做的一件事

買一組 Google Workspace Business Starter（US$7／人／月，8/30–11/30 五折），把 SHOP_SERVICE_EMAIL 從 ian890711@gmail.com 換成 service@chenkuanyi.com.tw。這跟寄信管道無關，是店面門面問題——那個位址印在每封信的頁尾和所有政策頁上。

7. 落地步驟

7.1 DNS（三筆記錄，缺一就進垃圾桶）

在 mail.chenkuanyi.com.tw 子網域上設：

  • SPF（TXT）—— Resend 後台會給。
  • DKIM（TXT 或 CNAME）—— Resend 後台會給。
  • DMARC（TXT，_dmarc.mail.chenkuanyi.com.tw）—— 要自己加，供應商不會給。先 p=none 觀察兩週，再收緊到 p=quarantine。
_dmarc.mail.chenkuanyi.com.tw. TXT "v=DMARC1; p=none; rua=mailto:service@chenkuanyi.com.tw; pct=100"

7.2 主機上的 .env.production

照 CLAUDE.md 的規矩：環境變數不走 scp，直接改主機那份，改完 chmod 600 再重建容器。

SMTP_HOST=smtp.resend.com
SMTP_PORT=465
SMTP_SECURE=true
SMTP_USER=resend
SMTP_PASS=<API key>
MAIL_FROM="莎岡選品店 <no-reply@mail.chenkuanyi.com.tw>"
SHOP_SERVICE_EMAIL=service@chenkuanyi.com.tw
ssh root@103.1.221.67 'cd /srv/sagon && cp -a .env.production ".env.production.bak-$(date +%m%d-%H%M)" && nano .env.production && chmod 600 .env.production && docker compose -f docker-compose.prod.yml up -d --force-recreate web worker'

7.3 驗證（這就是 L-05 / M-8 要做的事）

  1. 寄一封到 mail-tester.com，目標 10/10。低於 8 分先別上線。
  2. 走完一筆真實訂單，確認四種信都收得到、不在垃圾信匣，寄件者名稱與回覆地址正確。
  3. 開 Google Postmaster Tools 綁 mail.chenkuanyi.com.tw，開站後兩週回頭看垃圾申訴率（目標 < 0.1%）。
  4. 刻意寄一封到不存在的信箱，確認 Resend 後台看得到 hard bounce，且 worker 不會無止盡重試。
  5. 兩週後把 DMARC 從 p=none 收緊到 p=quarantine。

8. 需要你決定的事

  1. chenkuanyi.com.tw 的 DNS 在哪裡管？（Cloudflare／中華電信／註冊商後台）——這決定 SPF／DKIM／DMARC 怎麼加，以及要不要注意「Cloudflare 的 proxy 不能開在 MX／TXT 上」這類細節。
  2. 要不要買 Google Workspace 當客服信箱？US$7／人／月，8/30–11/30 五折。不買的話 SHOP_SERVICE_EMAIL 就繼續用 gmail.com。
  3. 報帳上需不需要台灣統一發票？境外服務（Resend／AWS／Zoho）多半只有國外 invoice 與信用卡帳單。如果會計要求一定要有台灣發票，這會直接把天平推向電子豹——那就要接受改程式與月費。
  4. Resend 要免費方案還是直接上 Pro？我的建議是直接上 Pro（NT$640／月）買掉日上限風險；若堅持免費，請同時把 SES sandbox 先解好當備援。

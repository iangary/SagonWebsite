## 需要注意的三點

1. **沒有測試環境。** 三竹沒有 stage／sandbox，「測試點數」就是正式帳號裡的 300 點免費額度 ——
   意思是所有串接測試都打正式端點、發真的簡訊、扣真的點數。
   所以 [README.md](README.md) 第 3 步「先用不花點數的餘額查詢驗證連線」更重要了，
   不要拿發送去試錯。
2. **API 密碼就是網頁登入密碼。** 之後在後台改網頁密碼，會直接讓正式站的簡訊發送失效
   （`statuscode=e`），而且沒有任何預警。要改密碼就得同步更新
   本機 `docs/sagon-deploy/.env.production` 的 `MITAKE_PASSWORD`、`scp` 上主機並重建 `web` 容器。
   規格書附錄二還有 `m`（必須變更密碼）、`n`（密碼已逾期）兩個狀態碼 ——
   代表三竹可能會強制要求換密碼，屆時簡訊會整組停掉。
3. **IP 變更要提前一個工作天。** 換主機、加第二台、或機房換 IP，都不能當天上線。

## 三竹沒有回答的問題

申請信裡沒問、但仍然懸著、需要下次接洽時補問的：

- **中文簡訊的單則計費字數上限**。規格書附錄四只規範純英數 160 字，中文全篇未提。
  目前 OTP 訊息約 38 字，以業界慣例的 70 字來看有邊際，但這是推測不是文件依據。
- **本帳號有沒有長簡訊發送權限**。沒有的話，超長內容會被**靜默截斷後照樣送出**
  —— 驗證碼被切掉是無聲故障。
- **`smbody` 內容含 `$$` 時在 `SmBulkSend` 的跳脫規則**。目前只發單筆 OTP 不受影響，
  日後做批次通知簡訊才需要。
